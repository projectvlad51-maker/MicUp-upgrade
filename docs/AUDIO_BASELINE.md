# Исходная конфигурация 1.0.6 и пользовательское звучание

MicUp 1.0.15 и Lite 1.0.3 возвращают техническую конфигурацию из предоставленного пользователем исходного архива [MicUp v1.0.6](https://github.com/papergray/MicUp/tree/v1.0.6). Изменения звучания оставлены отдельно от настройки потоков.

| Параметр | Исходная 1.0.6 | Обе новые сборки |
|---|---|---|
| Вход | VoiceCommunication, LowLatency, Exclusive, float, mono, 48000 Гц | Те же настройки builder, проверены сравнением с исходным кодом |
| Сеанс записи | Стандартный, без setSessionId | Восстановлено; SessionId::Allocate из предыдущих сборок удалён |
| Системные эффекты входа | Нет ручного подключения AEC/NS | Дополнительные контроллеры удалены; исходный профиль VoiceCommunication остаётся |
| Нативный выход | VoiceCommunication/Speech, нулевые сэмплы после callback | Сохранено |
| Реальное воспроизведение | Один AudioTrack, USAGE_MEDIA/CONTENT_TYPE_SPEECH | Сохранено в общем SoftwareLoopback для full/Lite |
| Аудиофокус | transient-may-duck, MEDIA/SPEECH | Сохранено |
| Аудиорежим телефона | Не переводится в MODE_IN_COMMUNICATION; при stop устанавливается MODE_NORMAL | Восстановлено |
| Ошибка устройства | Повторное открытие потоков | Восстановлено; неудачное открытие не выдаётся за работающий звук |
| Открытие приложения | Запуск после разрешения микрофона | Восстановлено; доступна явная кнопка остановки |
| Фоновый сервис | START_STICKY при успешной работе | Восстановлено; ошибки/явная остановка не запрашивают перезапуск |
| Прослушивание | Включено по умолчанию, можно выключить | Исходный default восстановлен один раз при обновлении, дальнейший выбор сохраняется |
| Устройства | Auto: подключённые наушники, затем разговорный динамик | Тот же выбор; явный пользовательский выбор может его изменить |

Четыре исходных пункта возвращены в обе версии, выбор сохраняется отдельно от пресетов:

| Пункт | Состояние |
|---|---|
| VoIP Compatible | Исходный обычный аудиотракт, без root; настройки транспорта не меняются |
| Software Loopback | Исходный обычный аудиотракт, без root; настройки транспорта не меняются |
| Shizuku — ADB Level | Видим и выбирается, но передача через системный виртуальный вход недоступна: такой бэкенд не реализован в исходном архиве |
| Root Mode — System-Wide | Видим и выбирается, но требуются root и системный аудиомодуль, отсутствующий в исходном архиве |

Выбор недоступного пункта не объявляется успешной передачей и не запускает микрофон под видом другого режима. В полной версии сохранено отдельное управление подключением Shizuku. Сам факт выдачи Shizuku-разрешения не включает отсутствующий виртуальный аудиовход. В оригинальном ShizukuManager.execInternal команды запускались через Runtime.exec обычного sh, а файл micplugin_routing.zip, упомянутый VirtualMicService, отсутствует в архиве. Эти заглушки не копируются как работающие системные маршруты.

Проверка `python3 scripts/check_original_audio_config.py` сравнивает все параметры открытия потоков с первоначальным коммитом архива. Единственный разрешённый override — устройство входа, явно выбранное пользователем; при Auto настройки builder совпадают с исходником. Эта проверка выполняется также workflow публикации. Мутационные тесты проверяют, что случайное возвращение SessionId::Allocate или Shared вместо Exclusive обнаруживается.

Ваши настройки звучания: микрофон до +36 дБ, собственный вывод до +24 дБ, отдельный уровень, плавное усиление и ограничитель пиков, исходный Noise Gate с регулируемым порогом. В Lite остаются 10 пресетов уровней; EQ, компрессор, pitch и реверберация выключены. В полной версии остаются эффекты, плагины, исправленные крутилки и отдельные регуляторы. Пресеты Lite не меняют устройства, прослушивание и шумоподавление. Сохранены тихий статус сервиса и управление подключением Shizuku в полной версии.

При переходе на эту конфигурацию один раз сбрасываются только параметры вывода: устройства Auto, прослушивание включено, уровень 100%; уровни усиления, пресет и настройки шумоподавления сохраняются. Очистка всех данных/переустановка не требуются. Именованный JNI callback сохранён для корректной работы оптимизированной Lite.

Это сравнение конфигурации и автоматические проверки, а не проверка звонка на физическом Pixel 9 Pro. В исходнике C++ передаёт сэмплы Kotlin и обнуляет нативный выход; AudioTrack воспроизводит их локально. Системный виртуальный вход для Discord/Telegram/WhatsApp в обычном VoIP-пути не реализован. Исходные обещания README не используются как доказательство такой функции. Android может ограничивать одновременную запись независимо от MicUp.
