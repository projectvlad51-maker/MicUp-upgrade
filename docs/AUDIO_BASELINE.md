# Возврат к исходному аудиотракту

База сравнения: исходный архив [MicUp v1.0.6](https://github.com/papergray/MicUp/tree/v1.0.6) и локальный тег `micup-v1.0.10` — последняя рабочая версия по сообщению пользователя. Описание README исходника сравнивалось с реально исполняемым кодом.

| Участок | Исходник / 1.0.10 | 1.0.14 и Lite 1.0.2 |
|---|---|---|
| Захват | Oboe, VoiceCommunication, запрос Exclusive/LowLatency, моно float 48 кГц | Та же реализация AudioEngine.cpp; выделение сеанса сохранено для системных AEC/NS |
| Обработка | Нативная цепочка, callback в Kotlin | Общая цепочка; Lite оставляет Noise Gate и усиление, выключает EQ/компрессор/реверберацию/pitch/частотные срезы |
| Воспроизведение | Native output обнуляется, играет только очередь SoftwareLoopback | Один и тот же SoftwareLoopback.kt включён в оба приложения |
| Аудиофокус | Запрос transient-may-duck, в 1.0.10 с выбранными media/VoIP атрибутами | Восстановлен и для VoIP; сохраняется обработка потери/возврата фокуса |
| Звонок / конфликт записи | Нет проверки mode до старта и остановки по recording callback | Ограничения 1.0.13/1.0.1 удалены; ОС может ограничить запись независимо от MicUp |
| Проверка голоса | Управляет единственным локальным выводом | Отдельный сохраняемый переключатель, по умолчанию выключен согласно запросу пользователя |

Ваши доработки сохранены: исправленные крутилки, усиление микрофона до +36 дБ, усиление собственного вывода до +24 дБ, отдельные уровни, эффекты и плагины в полной версии, тихий статус фонового сервиса, настройки Shizuku, сохранение настроек и устройств, 10 пресетов уровней в Lite. Пресеты Lite не включают эффекты изменения тембра и не меняют порог шума/проверку микрофона/устройства. Выбор входа Lite передаётся в исходный Oboe builder; выход использует setPreferredDevice, как в исходном мониторинге.

Ограничитель пиков из прежней Lite перенесён в общий MicrophoneGain: он масштабирует блок, сохраняя форму пиков, вместо обрезания каждого сэмпла. Для Lite закреплён именованный JNI callback onAudioBuffer: R8 не переименовывает вызываемый из C++ метод. Это проверяется по mapping итоговой release-сборки.

Устранена ошибка пула очереди: после изменения размера callback не воспроизводится хвост старого буфера. Ошибки реального открытия/отключения устройства остаются ошибками; приложение не показывает работающий звук, если движок не стартовал.

В исходном C++ callback обработанные сэмплы передаются Kotlin, после чего нативный выход заполняется нулями. Реальное воспроизведение делает AudioTrack. Вызовы VoIP API и заявления README сами по себе не создают системный виртуальный микрофон; возвращение исходника не добавляет его. Работа обработанного голоса в Discord/Telegram/WhatsApp и совместная запись на Pixel 9 Pro с бета-Android требуют проверки на устройстве и не подтверждены облачными тестами.
